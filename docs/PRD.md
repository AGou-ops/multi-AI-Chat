# 多 AI 并行聊天客户端 PRD

## 1. 背景

用户希望构建一个跨 AI 平台的客户端应用，可以同时打开并使用 ChatGPT、Claude、Gemini、DeepSeek 等在线 AI 工具。第一版不接入各平台 API，不管理模型密钥，不做服务端会话编排，用户使用自己的平台账号手动登录。

前期已验证纯 Web iframe 方案不可行：主流在线 AI 平台普遍通过浏览器安全策略限制 iframe 嵌入。因此第一版转为桌面客户端方案，使用 Chromium 内核承载多个在线平台页面。

## 2. 第一版目标

第一版做一个 macOS Electron 客户端，提供多 AI 在线平台并行操作工作台。

核心目标：

- 同时展示多个在线 AI 平台页面。
- 用户可手动登录每个平台账号。
- 每个平台独立登录态，同一平台可复用登录态。
- 默认内置 ChatGPT、Claude、Gemini、DeepSeek。
- 用户可添加自定义平台 URL。
- 支持统一 prompt 输入、历史保存、搜索。
- 对内置平台提供 Beta 级自动填入能力。
- 可按平台单独开启自动发送。
- 不读取、不汇总、不保存 AI 回复内容。
- 产出可双击运行的 macOS 应用包。

## 3. 非目标

第一版明确不做：

- 不做 Web 版。
- 不做浏览器插件。
- 不做 iframe 嵌入方案。
- 不接入 OpenAI、Claude、Gemini、DeepSeek 等模型 API。
- 不管理用户 API Key。
- 不做服务端账号系统。
- 不做云同步。
- 不做计费。
- 不读取 AI 回复内容。
- 不保存完整聊天记录。
- 不做自动总结、对比、聚合回复。
- 不支持自定义平台注入脚本。
- 不做自动更新。
- 不做 Windows / Linux 打包。
- 不做平台级清除登录态/缓存入口。
- 不做完整权限管理页。

## 4. 目标用户

第一版面向需要同时对比多个在线 AI 平台输出的个人用户或研发用户。

典型使用场景：

- 同一个 prompt 同时发给多个 AI 平台。
- 并排观察多个平台的回复质量。
- 在多个平台之间快速切换和聚焦。
- 复用历史 prompt。
- 添加自己常用的在线 AI 工具。

## 5. 平台范围

默认内置平台：

- ChatGPT：`https://chatgpt.com`
- Claude：`https://claude.ai`
- Gemini：`https://gemini.google.com`
- DeepSeek：`https://chat.deepseek.com`

自定义平台：

- 用户可添加名称和 URL。
- 可配置图标 URL 或自动使用 favicon。
- 可配置自定义 User-Agent。
- 可配置默认布局尺寸。
- 可配置登录/授权白名单域名。
- 不支持自动填入、自动发送、自定义注入脚本。

## 6. 用户体验

### 6.1 主界面

采用工具型、密集、克制的工作台风格。

建议结构：

- 左侧平台栏：平台列表、启用状态、内置/自定义标识。
- 顶部 prompt 操作条：输入框、复制、填入、发送、目标平台选择。
- 中间主区域：多平台 Chromium 视图网格。
- 平台标题栏：平台名、加载状态、刷新、返回、前进、外部浏览器打开、聚焦。
- 右侧历史抽屉：prompt 历史、搜索、执行记录。
- 设置页：平台配置、历史保留策略、默认行为设置。

### 6.2 布局

第一版采用网格并排布局，并支持单窗口聚焦。

规则：

- 已启用平台自动进入网格。
- 支持 1 / 2 / 3 / 4 宫格。
- 点击平台进入聚焦模式。
- `Esc` 退出聚焦模式。
- 应用重启后恢复上次启用平台和布局偏好。

### 6.3 统一 prompt

顶部提供统一 prompt 输入框。

能力：

- 编写 prompt。
- 一键复制 prompt。
- 对内置平台执行自动填入。
- 对开启自动发送的平台执行填入后发送。
- 对失败平台显示失败原因，并复制 prompt 作为兜底。

## 7. 自动填入与自动发送

第一版支持内置平台的 Beta 自动化适配器。

支持范围：

- ChatGPT
- Claude
- Gemini
- DeepSeek

规则：

- 自动填入只针对内置平台。
- 自定义平台不支持自动填入。
- 自动发送按平台单独配置。
- 自动发送默认关闭。
- 开启自动发送的平台，在批量执行前需要二次确认。
- 不绕过登录、风控、验证码。
- 不读取回复。
- 不自动刷新页面。

失败处理：

- 每个平台最多重试 2 次。
- 每次重试间隔 1.5 秒。
- 只对输入框暂时未找到、页面仍在加载等可恢复失败重试。
- 未登录、权限拒绝、平台不支持、页面风控等失败不重试。
- 最终显示每个平台执行结果。
- 失败后自动复制 prompt，提示用户手动粘贴。

## 8. 本地数据

第一版只做本地持久化。

保存内容：

- 平台列表。
- 自定义平台配置。
- 启用状态。
- 布局偏好。
- User-Agent 配置。
- 登录白名单域名。
- 每个平台自动发送开关。
- prompt 历史。
- prompt 执行记录元数据。

不保存内容：

- AI 回复内容。
- 平台页面 HTML。
- 用户账号密码。
- Cookie 明文导出。
- 云端同步数据。

### 8.1 prompt 历史

规则：

- 默认保存全部 prompt 历史。
- 支持简单关键词搜索。
- 支持一键清空。
- 支持保留策略：
  - 永久保存。
  - 最近 50 条。
  - 最近 200 条。
  - 最近 30 天。
  - 不保存。
- 明示本地存储路径。

### 8.2 执行记录元数据

每条 prompt 可保存：

- prompt 文本。
- 创建时间。
- 目标平台列表。
- 每个平台执行动作：复制、填入、发送。
- 每个平台执行结果：成功、失败、跳过。
- 失败原因。
- 自动重试次数。

## 9. 登录态

第一版采用每个平台独立登录态，同平台复用。

规则：

- ChatGPT 使用独立持久化分区。
- Claude 使用独立持久化分区。
- Gemini 使用独立持久化分区。
- DeepSeek 使用独立持久化分区。
- 自定义平台默认使用独立持久化分区。
- 同一平台多个视图复用同一个分区。

第一版不提供平台级清除登录态/缓存入口，用户可在对应平台网页中自行退出账号。

## 10. 链接与窗口策略

规则：

- 同域链接留在应用内打开。
- 登录/授权白名单域名留在应用内打开。
- 跨域非白名单链接使用系统浏览器打开，并提示用户。
- 新窗口请求统一拦截后按上述规则处理。

内置平台维护默认登录白名单。自定义平台允许用户添加白名单域名。

## 11. 权限策略

第一版不做权限管理页。

基础规则：

- 麦克风、摄像头、通知、剪贴板等权限默认询问。
- 下载默认询问保存位置，或先禁用自动下载。
- 弹窗和新窗口请求统一拦截。
- 不做权限历史记录。
- 不做平台级长期允许/拒绝配置。

## 12. 快捷键

第一版支持少量核心快捷键：

- `Cmd+Enter`：对选中平台执行填入/发送。
- `Cmd+Shift+Enter`：对所有启用平台执行填入/发送。
- `Cmd+L`：聚焦 prompt 输入框。
- `Cmd+1/2/3/4`：聚焦第 N 个平台。
- `Esc`：退出聚焦模式。
- `Cmd+F`：搜索历史。

第一版不做自定义快捷键系统。

## 13. 崩溃与卡死恢复

最低限度恢复能力：

- 平台加载失败时显示错误状态和重试按钮。
- 平台渲染进程崩溃时显示重新加载入口。
- 单个平台异常不影响整体应用可用性。
- 应用重启后恢复上次启用平台和布局偏好。
- 不做崩溃日志上传。
- 不做自动重启崩溃平台视图。

## 14. 打包与发布

第一版只支持 macOS。

要求：

- 开发模式可运行。
- 可构建生产包。
- 可产出 `.app` 或 `.dmg`。
- 不要求签名。
- 不要求公证。
- 不做自动更新。

## 15. 验收标准

自动化测试应覆盖：

- 应用基础启动。
- 默认平台配置存在。
- 自定义平台增删改。
- 平台持久化分区配置正确。
- URL 白名单规则。
- prompt 历史保存。
- prompt 历史搜索。
- 执行记录元数据保存。
- 快捷键事件触发。
- 打包命令可执行。

手工验收应覆盖：

- ChatGPT 页面可加载并登录。
- Claude 页面可加载并登录。
- Gemini 页面可加载并登录。
- DeepSeek 页面可加载并登录。
- 多平台网格布局正常。
- 单平台聚焦和退出聚焦正常。
- prompt 可复制。
- 内置平台自动填入可用或正确失败降级。
- 开启自动发送的平台执行前有确认。
- 自动化失败时显示平台级结果。
- 跨域非白名单链接在系统浏览器打开。
- 应用重启后配置和历史仍在。
- macOS 打包产物可双击启动。
